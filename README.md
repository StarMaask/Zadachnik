# Корпоративный «Ежедневник» (Android / Kotlin / Jetpack Compose)

Production-ready корпоративное Android-приложение для управления производственными задачами участка, фотоотчётности с площадки, приёмки работ по иерархии **Руководитель → ИТР → Рабочий**, ролевой аналитики и генерации официальных отчётных документов (**PDF, XLSX, DOCX, CSV**) в одном листе или на раздельных листах.

---

## 1. Архитектура и стек технологий

- **Архитектура**: Clean Architecture + MVVM + Unidirectional Data Flow (`StateFlow` / `collectAsStateWithLifecycle`).
- **UI**: 100% Jetpack Compose, Material Design 3, Industrial Precision палитра (`#0F2942` Navy, `#D97706` Safety Amber, `#15803D` Emerald, `#B91C1C` Crimson), типографика `Manrope` + `Inter`, поддержка адаптивных экранов и `enableEdgeToEdge()`.
- **Хранение и синхронизация (Offline-First)**:
  - **Firebase Firestore** (выделенная БД `ai-studio-android-4226c707-0da4-4c25-89ac-248f3f255608`) со встроенным локальным offline-кэшем Firestore SDK, очередью исходящих изменений и автоматической синхронизацией при восстановлении сети.
  - **Firebase Authentication + Jetpack Credential Manager** (`GetSignInWithGoogleOption`) для безопасного входа через корпоративный/Google-аккаунт.
- **Камера и медиа**:
  - Съёмка прямо из карточки задачи через `ActivityResultContracts.TakePicture` + `FileProvider` с автоматическим сжатием JPEG (до 1280px, качество 82%) и нанесением водяного знака (штамп времени, исполнитель, GPS-координаты/объект).
  - Поддержка системного `PickVisualMedia` (Zero-Permission Photo Picker).
- **Генератор отчётных документов (`ReportDocumentGenerator`)**:
  - Нативная генерация **PDF** (`android.graphics.pdf.PdfDocument` формата A4 альбомной ориентации с табличной сеткой и блоками подписей), **XLSX** (стандарт OpenXML SpreadsheetML `.xlsx` с поддержкой одного или двух раздельных листов `Лист 1 — План работ` и `Лист 2 — Отчёт за день`), **DOCX** (OpenXML WordprocessingML `.docx` с таблицами и реквизитами) и **CSV** (UTF-8 BOM для корректного открытия кириллицы в Microsoft Excel).

## 2. Принятые архитектурные и продуктовые допущения

1. **Переключение ролей для демонстрации и приёмки**:
   - В реальной эксплуатации роль сотрудника назначается Руководителем участка. Для удобства приёмки и тестирования всех трёх уровней иерархии (`Руководитель`, `ИТР`, `Рабочий`) на одном устройстве в верхней панели и в разделе «Профиль» предусмотрен переключатель демо-стенда роли с записью события в `AuditLog`.
2. **Офлайн-совместимость фотоотчётов**:
   - Чтобы приложение мгновенно работало в закрытых цехах без интернета и не требовало внешнего S3-бакета для запуска, фотографии сжимаются, маркируются штампом времени/геопозиции и сохраняются локально в защищённом кэше приложения + синхронизируются с метаданными и миниатюрой в документе задачи.
3. **Автоматический перенос задач в конце смены (`Carryover`)**:
   - При каждом открытии смены (а также по кнопке «Перенос смены» на главном экране) все задачи со статусами `NEW`, `IN_PROGRESS`, `REJECTED` и `OVERDUE`, у которых плановая дата меньше текущего дня, автоматически переносятся на текущий день. При этом `originalDueDateEpochDay` сохраняется неизменным, счётчик `carryoverCount` увеличивается, а в `carryoverHistory` и `AuditLog` добавляется запись о переносе. Задачи в статусах `APPROVED`, `CANCELLED` и `ARCHIVED` не переносятся.
4. **Независимая генерация XLSX/DOCX без тяжёлых jar-зависимостей**:
   - Для избежания раздувания APK (проблемы 64K методов Apache POI на Android) генератор формирует валидные контейнеры OpenXML (`.xlsx` и `.docx`) напрямую через `ZipOutputStream` со строгим экранированием XML-сущностей и полной поддержкой многолистовых книг Excel (`xl/worksheets/sheet1.xml`, `xl/worksheets/sheet2.xml`).

## 3. Ролевая модель и матрица прав (RBAC)

| Возможность | Рабочий (`WORKER`) | ИТР (`ITR`) | Руководитель (`HEAD`) |
| :--- | :---: | :---: | :---: |
| Создание личных задач себе | Да | Да | Да |
| Постановка задач Рабочим | Нет | Да | Да |
| Постановка задач ИТР и всему участку | Нет | Нет | Да |
| Выполнение задач и прикрепление фото с камеры | Да | Да | Да |
| Проверка и подтверждение/отклонение отчётов Рабочих | Нет | Да | Да |
| Проверка и подтверждение отчётов ИТР и любых групп | Нет | Нет | Да |
| Визуальное зачёркивание подтверждённых задач (`APPROVED`) | Да | Да | Да |
| Просмотр статистики | Личная + агрегат своей бригады (без чужих ФИО) | Своя + пофамильно подчинённые рабочие + бригада | Все сотрудники и все бригады участка |
| Выгрузка отчётности (PDF / XLSX / DOCX / CSV) | Только личная отчётность | Личная + сводная по подчинённым с ФИО | Полная сводная по всему персоналу участка |
| Управление шаблонами, бригадами и просмотр журнала аудита | Нет | Чтение шаблонов | Полный доступ + журнал аудита |

## 4. Запуск проекта и тестирование

### Локальная сборка и тесты
- Сборка отладочного APK:
  ```bash
  gradle :app:assembleDebug
  ```
- Запуск модульных тестов (проверка RBAC, генератора отчётов в 1 и 2 листа, ролевой статистики):
  ```bash
  gradle :app:testDebugUnitTest --tests 'com.example.ExampleUnitTest'
  ```
- Запуск интеграционных тестов безопасности Firestore Rules (Robolectric + Firestore Emulator):
  ```bash
  gradle :app:testDebugUnitTest --tests '*Rule*'
  ```

## 5. Автоматическая сборка `.apk` в GitHub Releases (CI/CD)

В репозитории настроен workflow **`.github/workflows/android-release.yml`**, который автоматически собирает и публикует готовые к установке `.apk` файлы при каждом пуше в ветки `main` / `master` или при создании тега `v*`:

1. При пуше кода в GitHub автоматически запускается раннер `ubuntu-latest` с JDK 17 и Android SDK.
2. Если в репозитории не закоммичен `app/google-services.json`, workflow автоматически использует секрет `GOOGLE_SERVICES_JSON` (или создаёт совместимый конфигурационный файл для успешной сборки).
3. Выполняется сборка `./gradlew assembleDebug assembleRelease` (при отсутствии `debug.keystore` он автоматически генерируется через `keytool`).
4. Собранные пакеты переименовываются в:
   - `Ezhednevnik-v1.0.<run_number>-release.apk`
   - `Ezhednevnik-v1.0.<run_number>-debug.apk`
5. Оба `.apk` файла прикрепляются к **GitHub Artifacts** и автоматически публикуются в разделе **GitHub Releases** репозитория (`softprops/action-gh-release@v2`), откуда их можно сразу скачать на телефон и установить.
